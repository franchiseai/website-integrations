Create a password account and request confirmation

Pending-intake capability supplies identity/context. Does not attach data to an existing account without ownership proof. Enforce password policy and account/email idempotency. No website Portal session. Public outcome deliberately does not expose account existence; the prototype returning scenario is not an account lookup contract.

Start Google or LinkedIn continuation

Create a single-use server transaction bound to intake, brand, provider, browser initiation and approved destination. Server validates provider tokens and email proof at callback. Different/missing/unverified email never silently claims intake. Final session exists only at hosted Portal, never on customer website. Cancellation/expiry recovery and browser binding require review before implementation.
